## หมวด 1: Business Model, รายได้ และกติกาโฆษณา (5 ข้อ)
**ผู้รับผิดชอบ:** พี่คิง (ร่วมกับ ลูกแก้ว)

1. **สิทธิ์การใช้งานผู้ใช้ทั่วไป:** ผู้ใช้ทั่วไปใช้งานฟรี 100% ทุกฟีเจอร์หลักตลอดไป หรือมีแผนเก็บค่าสมาชิก/จำกัดจำนวน (เช่น จำนวนตัวแมว หรือโควตา Cat AI)?
2. **รายได้จากร้านค้า / คลินิกบน Nearby:** ร้านค้า คลินิกสัตว์ หรือโรงแรมแมวที่ขึ้นหมุดใน Nearby ใช้งานฟรีพื้นฐานทั้งหมด หรือมีแพ็กเกจเสียค่าใช้จ่าย (เช่น ปักหมุดเด่น, ยืนยันตัวตนร้านค้า, แสดงโปรโมชัน)?
3. **กติกาการโพสต์และโฆษณาใน Feed:** ผู้ใช้ทั่วไปหรือร้านค้าสามารถโพสต์ขายของ/โฆษณาใน Feed ได้หรือไม่ — ต้องมีกฎห้ามขายตรง, บังคับติดแท็กโฆษณา/สปอนเซอร์, หรือเปิดระบบบูสต์โพสต์?
4. **ส่วนแบ่งรายได้สินค้า Tag และส่งขนม (Phase 2):** ช่องทางรายได้จากการขาย `แมว.live Tag` และระบบส่งขนม (`GIFT-01..06`) คิดโครงสร้างค่าธรรมเนียม/ส่วนแบ่งอย่างไร และใครเป็นผู้ออกใบเสร็จ/จัดการภาษี?
5. **สถานะเคสบริจาค (`DEC-11` / `DON-00`):** ทีมงานใดเป็นผู้ตรวจสอบรับรองมูลนิธิ/ผู้รับเงินบริจาค และฝ่ายกฎหมาย (Legal) คาดว่าจะตรวจข้อกำหนดการเรี่ยไรเสร็จเมื่อไร?

## หมวด 2: การต่อยอดเป็น "หมา.live" (Multi-Species Readiness) (4 ข้อ)
**ผู้รับผิดชอบ:** พี่คิง / ลูกแก้ว

6. **รูปแบบแอป "หมา.live":** หลังจบ `แมว.live` แล้ว `หมา.live` จะทำเป็น **แอปแยกคนละตัวบน Store** (ใช้ Codebase เดียวกันแบบสลับธีม/Config) หรือ **รวมในแอปเดียว** ให้ผู้ใช้เลือกสัตว์เลี้ยง?
7. **ขอบเขตข้อมูลที่ต้องแยกตามชนิดสัตว์เลี้ยง (Species-specific):** ส่วนไหนบ้างที่ต้องออกแบบโครงสร้างแยกตั้งแต่ Phase 1 (เช่น ตารางสายพันธุ์, โปรแกรมวัคซีน/สุขภาพ, Prompt ของ Cat AI vs Dog AI, ขนาด Tag/ปลอกคอ)?
8. **โครงสร้างฐานข้อมูลและชุมชนหลังบ้าน:** ข้อมูล Feed, Nearby และ Help ของแมวกับหมาจะใช้ **Database / Backend กลางชุดเดียวกัน** (แยกด้วยฟิลด์ `species`) หรือแยกคนละโปรเจกต์/คนละเซิร์ฟเวอร์?
9. **บัญชีผู้ใช้ข้ามแอป (Single Account):** ถ้าแยก 2 แอป ผู้ใช้ที่สมัคร `แมว.live` จะใช้บัญชีเดิมล็อกอิน `หมา.live` ได้เลยหรือไม่ (เพื่อเตรียม Auth กลางให้รองรับตั้งแต่ต้น)?

## หมวด 3: ขอบเขตหน้าจอ Navigation และจุดตกหล่น Prototype vs Spec (5 ข้อ)
**ผู้รับผิดชอบ:** ลูกแก้ว (PM) / พี่คิง

10. **จำนวนแท็บเมนูหลัก (`DEC-07`):** ยืนยันเลือกแบบไหน — **5 แท็บ** ตามสเปกใหม่ (`Feed / My Cat / Cat AI / Nearby / Help` โดยยุบหน้าแรกเข้า My Cat) หรือ **6 แท็บ** ตามเว็บต้นแบบ `www.แมว.live` (มีหน้าแรก `/` แยก + ปุ่มเมนู Hamburger)?
11. **แท็บในฟีดและฟีเจอร์ Story (`DEC-03`):** ยืนยันใช้แท็บฟีด 3 แท็บ (`ทั้งหมด / ติดตาม / บันทึกไว้`) + ตัวกรองหมวดหมู่เลยใช่ไหม และยืนยันถอดฟีเจอร์ **Story** ออกจากทุกเฟสถาวร?
12. **จุดตกหล่นระหว่าง Prototype เดิมกับสเปก:** ในเว็บต้นแบบมีปุ่ม/หน้าหลายส่วนที่ถูกย้ายไป Phase 2 (เช่น `เลี้ยงขนม`, `Tracker ตามหาแมว`, `Cat AI โทร/ตรวจหน้าแมว`, `หมวด Nearby อื่น`) — ใน Phase 1 ให้ **ซ่อนด้วย Feature Flag** หรือ **แสดงปุ่มพร้อมป้าย "เร็ว ๆ นี้"**?
13. **ขอบเขต Phase 2 (`F-CAT-07`, `F-CAT-10`):** ยืนยันว่าฟีเจอร์ **Memories** และ **สถานะแมวจากไปแล้ว (Memorial)** อยู่ใน Phase 2 แน่นอนใช่ไหม และมีหน้าไหนใน Prototype เดิมที่ยังไม่ได้บันทึกในสเปกอีกหรือไม่?
14. **การกรอกสายพันธุ์แมว (`DEC-02`):** ยืนยันว่า Phase 1 ใช้ฟอร์มเลือก/พิมพ์สายพันธุ์เอง แล้วค่อยเพิ่ม **AI เดาพันธุ์ (`AI-09`)** ใน Phase 2 ใช่ไหม?

## หมวด 4: การยืนยันตัวตน (Auth), สิทธิ์ผู้ดูแลร่วม & PDPA (5 ข้อ)
**ผู้รับผิดชอบ:** พี่เอกชัย / ลูกแก้ว

15. **สิทธิ์ Guest Mode vs Member (`DEC-08` / `AUTH-01..04` — ใครเห็นอะไร / ทำอะไรได้บ้าง):** ขอสรุป **Permission Matrix** ระหว่างผู้เยี่ยมชม (**Guest**) กับสมาชิก (**Member**) ครบทุกแท็บ — Guest ดู Feed, Nearby, Help และหน้า Cat ID สาธารณะได้โดยไม่ต้องล็อกอิน แต่โพสต์ คอมเมนต์ แชท DM เพิ่ม/ดูสมุดสุขภาพแมว ถาม Cat AI และตั้งค่าบัญชีต้องเข้าสู่ระบบก่อนใช่หรือไม่ (และ Phase 1 ต้องเปิดครบทั้ง 4 ช่องทาง: เบอร์+OTP, Apple, Google, LINE เลยไหม)?
16. **กติกา SMS OTP และแนวทางลดต้นทุนแฝง (`AUTH-03`):** เพื่อคุมค่าใช้จ่ายแฝงของ SMS OTP (~0.35–0.80 บาท/ข้อความ) ให้ใช้ SMS OTP เฉพาะตอนสมัคร/ยืนยันเบอร์ครั้งแรกหรือเปลี่ยนเครื่อง ส่วนครั้งถัดไปใช้ Session Token / PIN / Face ID แทนได้ไหม และเน้น Apple / Google / LINE เป็นช่องทางหลัก? (พร้อมยืนยันค่า OTP หมดอายุ **5 นาที**, ขอใหม่หลัง **60 วินาที**, ผิด **5 ครั้งล็อก 15 นาที**, และผู้ให้บริการ SMS เจ้าใด)
17. **สิทธิ์ผู้ดูแลร่วมรายแมว (`F-CAT-03` / Household RBAC):** ยืนยันตารางสิทธิ์ 3 ระดับ (**Owner / Caregiver / Viewer**), อายุลิงก์คำเชิญ **7 วัน** และขั้นตอนการโอนสิทธิ์ `Owner` ให้คนอื่นตามเอกสาร PRD ใช่หรือไม่?
18. **การตรวจอายุผู้ใช้งาน (`PDPA-03`):** ยืนยันกติกา — อายุต่ำกว่า **13 ปี** สมัครไม่ได้, อายุ **13–19 ปี** ต้องได้รับความยินยอมผู้ปกครองก่อนชำระเงิน — วิธีเก็บความยินยอมผู้ปกครองใน Phase 1 ใช้แค่ Checkbox ยืนยันหรือต้องมีขั้นตอนยืนยันตัวตนเพิ่ม?
19. **การส่งออกและขอลบข้อมูล (`PDPA-02` / `AUTH-05`):** ยืนยันรูปแบบไฟล์ส่งออกข้อมูลส่วนตัว (**JSON + PDF**) และระยะเวลาหน่วง **30 วัน** ก่อนลบข้อมูลถาวรเมื่อผู้ใช้กดลบบัญชี?

## หมวด 5: ระบบ AI (Cat AI, OCR, Moderation) และโควตา (5 ข้อ)
**ผู้รับผิดชอบ:** พี่เอกชัย / พี่คิง / ลูกแก้ว

20. **ผู้ให้บริการ AI หลัก (`DEC-05`):** สรุปเลือกใช้ผู้ให้บริการเจ้าใดสำหรับ 3 งาน — **LLM แชทสุขภาพแมว**, **Vision / OCR** (อ่านสมุดวัคซีน/ใบเสร็จ), และ **STT ภาษาไทย** (แปลงเสียงเป็นข้อความ)?
21. **กติกา Draft-first สำหรับ OCR (`DEC-01` / `F-HLT-03`):** ยืนยันว่าผลจาก OCR และ Cat AI ต้องขึ้นเป็น **"ร่าง (Draft)"** ให้ผู้ใช้ตรวจแก้และกดยืนยันก่อนบันทึกลง Health Timeline เสมอใช่ไหม?
22. **โควตาการใช้งาน AI (`AI-POL`):** ตัวเลขโควตาเสนอ (**50 ข้อความ/วัน** และ **โทร AI 20 นาที/วัน** ใน Phase 2) เหมาะสมกับงบประมาณค่า API แล้วหรือไม่ หรือต้องปรับเพดาน?
23. **การเก็บประวัติแชท AI (`AI-POL`):** ยืนยันระยะเวลาเก็บประวัติและผลประเมินคำตอบ AI **180 วัน** เพื่อตรวจคุณภาพ และยืนยันนโยบายไม่นำไปฝึกโมเดลหากผู้ใช้ไม่ยินยอม?
24. **ผู้ตรวจทานเนื้อหาสุขภาพ (`DEC-05`):** ใครหรือทีมสัตวแพทย์ใดเป็นผู้ตรวจรับรอง Prompt และข้อความกำกับ (Disclaimer) ของ Cat AI ก่อนเปิดใช้งานจริง?

## หมวด 6: แมวหาย, แผนที่ Nearby และ Notification (5 ข้อ)
**ผู้รับผิดชอบ:** ลูกแก้ว / พี่เอกชัย

25. **แหล่งข้อมูลแผนที่และสถานที่ Nearby (`DEC-04`):** ยืนยันใช้ **Google Places + ข้อมูลคลินิกที่ทีม Ops ตรวจ** ใช่ไหม (ค่า API อยู่ในงบที่วางไว้หรือไม่) และ Phase 1 เปิดเฉพาะหมวดคลินิก/โรงพยาบาลสัตว์ก่อนใช่ไหม?
26. **ความละเอียดพิกัดประกาศแมวหาย (`DEC-04` / `F-HELP-01`):** ยืนยันการแสดงพิกัดบนแผนที่สาธารณะแบบประมาณรัศมี **500 เมตร** เพื่อป้องกันการเปิดเผยที่อยู่บ้านเจ้าของแมว?
27. **การแจ้งเตือนแมวหายใกล้ตัว (`F-HELP-05`):** ยืนยันเงื่อนไขแจ้งเตือนผู้ใช้ในรัศมี **3 กม.** ภายใน **5 นาที** และจำกัดไม่เกิน **3 ครั้ง/วัน/ผู้ใช้**?
28. **อายุลิงก์ Vet Summary และประกาศค้าง (`F-HLT-04` / `F-HELP-06`):** ยืนยันระยะเวลา — ลิงก์ Vet Summary หมดอายุใน **72 ชั่วโมง** และแจ้งเตือนปิดประกาศแมวหายที่ไม่มีความเคลื่อนไหว **30 วัน + 7 วัน**?
29. **ช่วงเวลาห้ามรบกวน (`NOTI-01..03`):** ยืนยันช่วงเวลาห้ามรบกวน **22:00–07:00 น.** โดยอนุญาตเฉพาะแจ้งเตือน **"เตือนทานยา"** และ **"มีคนพบแมวหาย"** เท่านั้นใช่ไหม?

## หมวด 7: สินค้า Tag, การชำระเงิน, ขนม (Phase 2) และ Store Rules (5 ข้อ)
**ผู้รับผิดชอบ:** พี่คิง / ลูกแก้ว / พี่เอกชัย

30. **การสั่งซื้อ Tag บน iOS (`DEC-09` / `TAG-02` / `STORE-01`):** ยืนยันแนวทางบน iOS Phase 1 ที่แสดงรายละเอียด/3D Tag แล้วให้กด **"สั่งซื้อบนเว็บ"** เปิดเบราว์เซอร์ภายนอก (ไม่มีหน้าจ่ายเงินในแอป) เพื่อผ่านการตรวจของ App Store ใช่ไหม?
31. **ผู้ให้บริการชำระเงิน Android & Web (`TAG-02`):** การจ่ายผ่าน **QR PromptPay และบัตรเครดิต/เดบิต** บน Android และเว็บ จะเชื่อมต่อ Payment Gateway เจ้าใด (เช่น Omise, 2C2P, Stripe)?
32. **นโยบายคืนเงินและใบเสร็จ Tag (`TAG-05`):** ยืนยันเงื่อนไขคืนเงินเมื่อสินค้าเสียหายหรือไม่ได้รับภายใน **14 วัน** พร้อมการออกใบเสร็จอิเล็กทรอนิกส์?
33. **กติการะบบส่งขนมล่วงหน้า (`DEC-06` / `GIFT-01..06`):** ตัวเลขเสนอสำหรับ Phase 2 (วงเงินผู้ส่ง **2,000 บาท/วัน**, คืนเงินอัตโนมัติถ้าผู้รับไม่กดรับใน **14 วัน**) ต้องการให้ยืนยันไว้เป็นกติกาเลยหรือรอสรุปพร้อม Phase 2?
34. **การแสดงผลเคสบริจาคใน Phase 1 (`DEC-11`):** ยืนยันให้หน้า Help แสดงเคสบริจาคตัวอย่างที่ทีมอนุมัติแล้วได้ แต่ **ปิดปุ่มรับเงินทั้งหมด** จนกว่า Legal จะตรวจเสร็จใช่ไหม?
