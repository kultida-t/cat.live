## A. โค้ดต้นแบบและ Repo

1. โค้ด prototype (`maew-live/`) ใน repo `jutamaslukkaew-stack/cat.live` เราเข้าถึงได้ไหม? จะ copy มาเป็นฐานใน repo `kultida-t/cat.live` หรือเริ่มเขียนใหม่เอาเฉพาะดีไซน์?
2. ถ้าเอาโค้ดมาใช้ มีเงื่อนไข/ลิขสิทธิ์อะไรต้องระวังไหม (เช่น รูป mock, ฟอนต์, โมเดล 3D)?
3. โครงสร้าง `maew-live-handoff/` กับ `maew-live-blueprint.md` มีไฟล์จริงส่งต่อให้ด้วยไหม?

## B. ตัวตนผู้ใช้ (Auth) — เอกสารไม่ได้กล่าวถึงเลย

4. ล็อกอินด้วยอะไร? (LINE / Google / เบอร์โทร+OTP / อีเมล) — คนไทยส่วนมากน่าจะ LINE หรือเบอร์โทร
5. ใช้งานฟีด/ดูประกาศโดยไม่ล็อกอินได้ไหม? หรือบังคับล็อกอินทุกหน้า?
6. มี role อื่นนอกจากเจ้าของแมวไหม? เช่น admin/ทีมงาน (รับรายงาน+เบาะแส), ร้านค้า/คลินิก (เจ้าของสถานที่), ผู้ให้บริการฌาปนกิจ — ถ้ามี พวกเขาเข้าผ่านหน้าไหน?

## C. ขอบเขตงาน (Scope)

7. ทำเวอร์ชันแรกถึงแค่ไหน? รายการหน้าทั้งหมดใน `PROJECT.md` คือ scope เต็ม หรือมีหน้าไหนเป็น "เร็ว ๆ นี้" เหมือนเพ็ดดีกรี/ประกันที่อยากตัดออกจาก v1?
8. เป้าหมาย v1 คือ web app (mobile-first) อย่างเดียว หรือมีแผนทำ native app ต่อ? (กระทบทางเลือกเทค เช่น อยากเก็บโค้ดไปทำ React Native/Capacitor ไหม)
9. ภาษาอังกฤษ (EN) ต้องทำจริงใน v1 หรือแค่เตรียมโครง i18n ไว้ก่อน?

## D. Cat AI

10. Cat AI ใช้โมเดล/บริการอะไร? (OpenAI, Gemini, อื่น ๆ — กระทบค่าใช้จ่ายและ PDPA ข้อมูลแชท)
11. "โทรคุยกับสัตวแพทย์ AI" คือ voice call จริง (สตรีมเสียงสองทาง) หรือแค่เสียงอ่านคำตอบ?
12. "ตรวจใบหน้าแมว" `/cat-ai/face-check` คือฟีเจอร์อะไรแน่ ๆ — วิเคราะห์อารมณ์/สุขภาพจากรูป? จริงหรือ mock?

## E. แมว.live Tag (ฮาร์ดแวร์)

13. มีฮาร์ดแวร์จริงหรือยัง? สเปกใน prototype เป็นค่าตัวอย่าง — ตัวจริงใช้เทคอะไร (GPS? Bluetooth? เครือข่าย crowd-find แบบ AirTag?)
14. v1 ต้องเชื่อม Tag จริงไหม หรือทำ UI รองรับไว้ก่อน (สมมติข้อมูลตำแหน่ง)?
15. Tag ขายผ่านแอปเลยไหม (ระบบสั่งซื้อ+ชำระเงิน) หรือเป็นเพจขายลิงก์ออก?

## F. เงินและการชำระ

16. "เลี้ยงขนม" จ่ายผ่าน QR — QR PromptPay ของใคร? มีเกตเวย์ที่ตั้งใจไหม (Omise/Stripe/2C2P/ธนาคารตรง)?
17. ระดมทุนในประกาศอุปการะ — เงินเข้าบัญชีใคร? แมว.live หักค่าธรรมเนียมไหม?
18. บัญชีรับบริจาคของผู้ใช้ — ต้องยืนยันตัวตนก่อนรับเงินไหม (KYC)?
